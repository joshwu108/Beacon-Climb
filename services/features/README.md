# services/features — shared climber-features.v1 computer

Gradle module `:features` (`com.beaconclimb.features`), plain Java 21: no Spring, no Flink, no
Kafka. It is the one implementation of `contracts/features/climber-features.v1.md` that the api's
synchronous recompute (the parity oracle of ADR-0004) and the Flink job (`:stream`, BC-0304) are
meant to share.

| class | origin | role |
|---|---|---|
| `FeatureComputer` | verbatim port of `com.beaconclimb.api.features.FeatureComputer` | `compute(rows, W)` → aggregates, `feature_as_of`, provenance checksum; de-duplicates to the highest revision per `attempt_id` and applies `occurred_at <= W` |
| `FeatureAggregates` | verbatim port | the eleven keys; `toJson()` is the RFC 8785 canonical text (the parity payload) |
| `GradeBandBuckets`, `GradeBand` | verbatim port | fixed band edges (§4) |
| `AttemptFeatureRow` | verbatim port | input row `(attempt_id, revision, route_variant_public_id, occurred_at, sent, grade_numeric nullable)` |
| `Jcs`, `Timestamps` | copies of the api's canonicaliser and RFC 3339 formatter | what `toJson()` and the checksum need |

"Verbatim" means only the `package` line and imports differed from the api sources when BC-0304
ported them; since commit 998e274 (BC-0306) the api depends on this module and its own copies are
deleted, so this is the single implementation and any change is made here only.

## Tests

* `FeatureComputerTest` and `ReferenceFeatures` are the api's tests ported unchanged.
* `FeatureComputerReferencePropertyTest`: 300 seeded random row multisets (duplicates, revisions,
  rows after W, ties, null grades) against the independent reference restatement.
* `GoldenFixturesTest`: the committed fixtures below are what the computer and the reference produce.

## Golden fixtures (`src/test/resources/golden/climber-features-v1/*.json`)

Generated by `./gradlew :features:generateGoldenFixtures` (`GoldenFixtureGenerator`, which runs the
ported computer over hand-built cases); never edited by hand. `GoldenFixturesTest` fails when a
file and the code disagree, so a contract change means regenerating and reviewing the diff. The
api-side follow-up replays the same files against `com.beaconclimb.api.features.FeatureComputer`
to prove the two copies agree; the `:stream` module replays them through the Flink operator
(`ClimberFeaturesGoldenTest`). The reader `GoldenFixture` lives in `src/testFixtures` so other
modules can load the files (`testImplementation(testFixtures(project(":features")))`).

One file per case:

```json
{
  "name": "03-window-edge-7d",
  "description": "rows at exactly W-7d ... and W-7d+1ms ...",
  "cutoff_w": "2026-10-14T14:00:00Z",
  "attempts": [
    {
      "attempt_id": "018f0000-0000-7000-8000-000000000001",
      "revision": 1,
      "route_variant_id": "synthetic-route-001:40",
      "occurred_at": "2026-10-07T14:00:00Z",
      "sent": true,
      "grade_numeric": 20.0,
      "status": "ACTIVE"
    }
  ],
  "expected": {
    "feature_as_of": "2026-10-14T14:00:00Z",
    "provenance_checksum": "<64 lowercase hex>",
    "aggregates_json": "<the canonical JCS text, compared byte for byte>"
  }
}
```

* `attempts` is the input **as delivered**: it may contain the same `attempt_id` at several
  revisions, identical duplicates, `RETRACTED` rows and rows after `cutoff_w`. An implementation
  under test first reduces it to the highest revision per `attempt_id` (the first listed among
  equal revisions), drops the rows whose current revision has `status = RETRACTED`
  (`GoldenFixture.activeRows()`), then computes at `cutoff_w`; the computer's own `occurred_at <= W`
  filter does the rest. The stream replays the rows as `ATTEMPT_RECORDED` (revision 1) /
  `ATTEMPT_CORRECTED` / `ATTEMPT_RETRACTED` events in ascending `occurred_at` order.
* `grade_numeric` is `null` for ungraded; `status` is `ACTIVE` or `RETRACTED`.
* `expected.feature_as_of` is `null` for an empty included set (the computer's value; the stream
  record substitutes `source_watermark` there, climber-features.v1.md §10).
* `expected.aggregates_json` is a JSON string holding the canonical text (keys sorted, no
  whitespace, ECMAScript number spelling); compare the text, not a parsed tree.
* Ids are deterministic v7-shaped UUIDs (`018f0000-0000-7000-8000-<n>`); `cutoff_w` is
  `2026-10-14T14:00:00Z` throughout.

Cases (16): empty; single sent attempt; window edges at exactly 7, 30 and 90 days (and +1 ms);
sessions exactly 3 h apart vs 3 h + 1 ms; ties by `attempt_id`; retracted excluded (including a
retraction listed before its superseded ACTIVE revision); ungraded band; 30 rows over 25 variants
(`recent_variant_ids` truncation to 20); fractional-second timestamps; `max_sent_grade_numeric_90d`
with nulls and unsent rows; revision de-duplication and identical duplicates; rows after W; grade
band edges.
