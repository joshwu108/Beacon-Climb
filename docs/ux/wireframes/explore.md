# Wireframe: Explore routes

Contract basis: `GET /v1/routes`, `GET /v1/routes/{route_variant_id}`, `GET /v1/me` (defaults) in `contracts/openapi.yaml` 1.0.0; PRD 3.1 Explore, US-02, FR-02; 06 section 5. Tokens: `../design-tokens.md` (board SVG grammar in section 6). Journey: `../journeys.md` J2.

## 1. Purpose

Browse the routes that are compatible with the climber's board and angle, filter by grade, and inspect one route on a drawn board. Shows what is known and what is not: missing style tags and thin grade evidence are stated in words, never hidden. The board SVG is the centerpiece; the list is the way to choose what the board shows.

Explore only reads the catalog. It does not rank, recommend or predict anything.

## 2. Wireframe, mobile (320-480px)

Route `/explore?board_id=&angle_deg=&grade_min=&grade_max=&route=<route_variant_id>`. All filter state and the selected route are URL state.

Filters disclosure content: Angle (number, defaults to `preferences.angle_deg`), Grade from / to (see needs contract change for label mapping), "Use these as my defaults" (secondary button) and "Clear filters". Applying filters resets the cursor.

Board SVG for the selected route: viewBox from the bounding box of `placements[].x/y` plus `--space-board-pad`; one glyph per placement per the grammar below; START and FINISH labels always on, other labels on focus/pin or when the "Labels" toggle in board controls is on.

### >= 1024px

Three zones in a grid inside `--size-content-max`: nav rail (left), a route column (filters + list, scrolls independently, 22rem) and the board column (board as large as available, sheet overlaps the board's lower edge as an `aside`, then becomes a right-hand panel at >= 1440). Selected-hold callout appears next to the hold instead of the bottom. Board/List toggle remains (List view is a table in the board column).

## 3. Fields and contract sources

| UI element | Contract source | Direction | Notes |
|---|---|---|---|
| Default board, angle chip | `GET /v1/me` `preferences.board_id`, `preferences.angle_deg` | read | if `preferences` is null, redirect to onboarding |
| Filter: board | query `board_id` on `GET /v1/routes` | write (query) | normally fixed to preferences |
| Filter: angle | query `angle_deg` (integer) | write (query) | |
| Filter: grade range | query `grade_min`, `grade_max` (numbers; the field is `grade_numeric`) | write (query) | numeric, not labels; see needs contract change |
| Page size, paging | query `limit` (1-100), `cursor`; response `next_cursor` (string or null) | both | "Load more" appends; null hides the button |
| Row: route name | `items[].name` | read | |
| Row: grade | `items[].grade_label` (nullable), `items[].grade_numeric` (nullable) | read | label primary; null both -> "Ungraded" |
| Row: evidence count | `items[].grade_observation_count` | read | 0 triggers the insufficient-data treatment |
| Row id for selection | `items[].route_variant_id` | read | placed in URL `route=` |
| Board holds | `GET /v1/routes/{route_variant_id}` `placements[].hold_id`, `x`, `y`, `role` (START, HAND, FOOT, FINISH) | read | only the selected route's holds exist in the contract |
| Route sheet | `RouteVariant.name`, `grade_label`, `grade_numeric`, `grade_observation_count`, `angle_deg`, `board_id` | read | |
| Style tags | `RouteVariant.tags[]` and `missing_tags` (boolean) | read | `missing_tags: true` -> explicit text "Style tags: not available for this route" |
| Synthetic stamp | `GET /v1/boards` `items[].synthetic` for the current `board_id` | read | stamp text "SYNTHETIC DEMO BOARD" |
| Hold callout | `placements[]` item | read | role in words, derived relative position, `hold_id` |
| "Use these as my defaults" | `PUT /v1/me/preferences` `board_id`, `angle_deg`, `initial_grade_band`, `goals` | write | sends the full existing preferences with changed `board_id`/`angle_deg` |
| "Log an attempt" | navigates to Attempt Log with `route_variant_id` | n/a | no request here |

Grade text rule: the grade is a community-average label, not a measure of physical difficulty (master plan assumption 6). Copy near the grade says "Community grade", and never "you can climb" or "easy for you".

## 4. Board and hold states on this screen

| State | Shape | Pattern | Text channel | Color (redundant) |
|---|---|---|---|---|
| START | circle with second concentric ring | solid | "START" label always on | `--color-hold-start` |
| HAND | circle | solid | "HAND" on focus/pin/labels-on | `--color-hold-hand` |
| FOOT | smaller rounded square | diagonal hatch | "FOOT" on focus/pin/labels-on | `--color-hold-foot` |
| FINISH | diamond with top bar | solid | "FINISH" label always on | `--color-hold-finish` |
| Selected (pinned) | outer 3px ring, 3px gap, check badge | ring | callout: "Selected"; `aria-pressed="true"` | ink |
| Recommended | not used here (Explore does not recommend) | | | accent not shown on this screen |
| Insufficient data | dotted outlines, hatch fill, "?" badge | dotted | stamp "NOT ENOUGH DATA" + caption "No logged grade observations for this route yet." | neutral |

Insufficient-data applies to the whole displayed route when `grade_observation_count == 0` or `grade_numeric == null`. The threshold for "enough" observations is a ranking policy value (06 section 9 `min_obs`) that the contract does not expose; Explore therefore only marks the zero case and otherwise prints the plain count.

Orientation: the renderer assumes `y` increases upward and flips once; this is unconfirmed (see needs contract change).

## 6. Accessibility

### Landmarks and headings

| Landmark | Content |
|---|---|
| `header` | brand, board/angle chip (text, button to Filters), synthetic stamp |
| `nav aria-label="Primary"` | Explore (`aria-current="page"`), Session, Log, More |
| `main` | everything below |
| `search aria-label="Route filters"` (or `form role="search"`) | filter disclosure |
| `section aria-labelledby` (board) | board view/list toggle, zoom buttons, SVG |
| `aside aria-label="Selected route"` | route sheet (bottom sheet on mobile, panel at >= 1024) |
| `section aria-labelledby` (routes) | route list |
| `footer aria-label="Data and privacy"` | data note |

Heading outline: `h1` "Explore routes"; `h2` selected route name (sheet); `h2` "Routes at <angle> degrees"; no heading levels skipped. Board SVG has `<title>`/`aria-labelledby` text: "Board view of <name>: <n> holds" and `aria-describedby` pointing to the legend.

### Keyboard path

Tab order: skip link ("Skip to main content") -> header chip -> primary nav (4 links) -> Filters disclosure -> angle -> grade from -> grade to -> Apply / Clear / defaults -> Board|List toggle -> zoom -out/-in/reset -> "Labels" toggle -> "Skip board" link -> **board (one tab stop, roving)** -> route sheet actions -> route list rows (one tab stop per row) -> Load more.

Board keys (focus on a hold):

| Key | Behaviour |
|---|---|
| Arrow keys | Move focus to the nearest hold in that direction (within a 90 degree cone); stay put if none |
| Home / End | First / last hold in reading order (top to bottom, left to right) |
| Enter or Space | Toggle pinned selection on the focused hold (`aria-pressed`); callout text updates |
| Esc | If a callout is open, close it and keep focus; otherwise move focus to the board frame (`tabindex="-1"`, labelled "Board") so Tab continues past the board |
| + / - / 0 | Zoom in / out / reset (board scrolls to keep focus visible) |
| Tab / Shift+Tab | Leaves the board (roving tabindex: exactly one hold has `tabindex="0"`) |

List view (the non-spatial equivalent): a `table` with columns Hold, Role, Position; rows are buttons toggling the same selection. Board and List views share selection state. Screen-reader users can stay entirely in List view; no information exists only in the SVG.

Route list rows: Enter or Space selects (`aria-current="true"` on the selected row), Up/Down moves between rows only if a roving pattern is adopted; v1 uses plain Tab per row (simplest, least risk).

Primary nav is before `main` in the DOM at every width so tab order equals reading order; on mobile CSS pins it to the bottom edge (fixed position, not reordered). The "Skip to main content" link keeps this to one extra stop.

### Focus and motion

- `:focus-visible` two-tone ring on every control; hold focus ring per tokens (3px ink, 2px gap), visible over the board face in both themes.
- Selecting a route moves focus to the sheet heading (`h2`, `tabindex="-1"`) only for keyboard-initiated selection; pointer selection does not move focus.
- Zoom and pan jump (no animation) under `prefers-reduced-motion: reduce`; sheet open is an opacity change; no pulse; skeleton shimmer disabled.
- Pointer: pinch-zoom is additive; +/- buttons and the list view cover all functionality (WCAG 2.5.1). Hold hit radius 22px, 44px target at 1x zoom.
- Pinned hold and zoom level are not persisted.

## 7. Needs contract change (this screen)

1. Board geometry: `Board` has no hold layout, extents, orientation (y up/down), units or outline, so only the selected route's placements can be drawn and the board frame is inferred. Proposed: `Board.holds[]` (hold_id, x, y), `Board.extent`, and a coordinate-system statement.
2. Available angles per board (`Board.available_angles`) for the angle control; currently free numeric entry.
3. Grade filter by label: `grade_min`/`grade_max` are `grade_numeric` numbers; the label-to-number table (BC-0014) is not exposed. Needs a grade table in the contract or documented static table.
4. `placement_order` on `Placement` (needed for sequence-aware displays).
5. `missing_tags` and `tags` exist only on `RouteVariant`, not `RouteVariantSummary`; the list cannot show or filter tags. Needs `missing_tags` on the summary, and a `tags` filter query when tags exist.
6. Hold-contained filter (routes that use hold X) is not available; v1 hold selection is inspection only.
7. `min_obs` (or a `grade_evidence` enum) to mark "thin evidence" beyond count zero.
8. Availability: `validation_status` (ACTIVE, RETIRED, INVALID) is not exposed; UI assumes the catalog endpoints return active routes only (US-02). Needs confirmation.
9. PRD 8.1 names the query `angle`; openapi uses `angle_deg`. UI follows openapi; PRD text should be corrected.
10. Total count (`total` or `estimated_count`) for "N routes match"; UI shows "12 loaded" only.
